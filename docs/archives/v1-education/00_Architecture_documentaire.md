# LIVE — Architecture documentaire de refonte du projet

## 0. Objet du chantier

Le présent document organise la réécriture complète du projet **Live**, plateforme numérique éducative, sociale, économique et intelligente destinée en priorité au Congo, puis extensible à d’autres pays.

La réécriture sera réalisée par documents Markdown autonomes mais cohérents entre eux. Chaque document devra pouvoir être relu, corrigé et validé séparément avant intégration dans un dossier final consolidé.

Le principe directeur est le suivant :

> Tout le monde entre sur Live comme utilisateur. Les fonctions de création, de publication officielle, de monétisation, d’administration ou de gestion institutionnelle sont accordées sous forme de capacités, d’abonnements, de vérifications et d’autorisations.

Aucun rôle figé ne sera imposé aux utilisateurs, à l’exception du **Super Administrateur**, responsable du contrôle global de la plateforme.

Chaque document validé sera considéré comme une brique stable du projet.

---

# 4. Point de départ recommandé

La réécriture doit commencer par le **Document 01 — Vision, identité et positionnement de Live**.

Ce choix est indispensable parce que toutes les décisions suivantes dépendent de la définition exacte du produit :

- ce que Live est ;
- ce que Live n’est pas ;
- pourquoi Live existe ;
- à qui Live s’adresse ;
- quelle valeur Live crée ;
- comment les différents modules restent cohérents ;
- comment la plateforme peut évoluer sans perdre son identité.

Le second document sera immédiatement consacré au **modèle économique**, afin de vérifier que la vision peut soutenir une économie viable pour Live, les créateurs, les institutions et les utilisateurs.

---

# 5. Principe de non-simplification

La réécriture ne devra pas supprimer les ambitions du projet. Elle devra :

- les organiser ;
- les hiérarchiser ;
- les rendre techniquement réalisables ;
- les rendre économiquement soutenables ;
- distinguer le MVP de la vision finale ;
- identifier les dépendances ;
- préciser les règles ;
- prévenir les risques ;
- conserver une architecture extensible.

La simplification ne concernera que l’ordre de déploiement, jamais la vision globale.
